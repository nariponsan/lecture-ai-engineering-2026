# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 同じ質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」で比べた（モデルはどちらも gemini-3.5-flash-lite）。
  - 第1回の素のLLM（app.ask）は講座の情報を持たないため、「基礎・応用・発展」ともっともらしく作り話をした。
  - エージェント（app.agent）は search_glossary で用語集を検索し、その結果を読んでから答える（LLM→ツール→LLMのループ）ため、「基礎・実装・発展、どれか1つで完了」と正しく答え、最後に関係する回（第1回）も示した。違いを生んだのは、ツールで外部の情報を取ってきて、ループでそれをLLMに読ませたこと。
  - ただし「宿題の難易度と内容の構成」の「難易度」や「ご自身の理解度や使える時間に合わせて」など、用語集の定義にない言葉を少し付け足していた。ツールで正しい情報を渡しても、LLMは言葉を足すことがある。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」：search_glossary({'query': '3レベル'})
  - 「LoRAとQLoRAの違いは？」：search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) の2回。search_glossary の docstring に「query には調べたい用語を1つだけ入れる」とあるため、用語ごとに分けて検索した。
  - 追加で「LoRA、QLoRA、PEFTの違いは？」：'LoRA'・'QLoRA'・'PEFT' の3回。
  - 「第2回の内容から確認問題を1問出して」：make_quiz({'lecture': 2})。「第2回」を整数の2にして渡した。
  - 補足：[tool return] の表示は画面用に120文字で切られているだけで、LLMは全文を受け取っている。

- 1つの質問での LLM 呼び出し回数（`requests`）：

  | 質問 | requests | tool_calls | input_tokens |
  |---|---|---|---|
  | 3レベル | 2 | 1 | 783 |
  | LoRAとQLoRA | 2 | 2 | 1196 |
  | LoRA・QLoRA・PEFT | 2 | 3 | 1417 |
  | 第2回の確認問題 | 2 | 1 | 869 |

  - どの質問でも requests=2。1回目でLLMがツールの呼び出しを依頼し、プログラムがツールを実行し、2回目でLLMが結果を読んで回答した。ツールの実行はLLMではないので requests に数えない。
  - 用語が2つ・3つの質問では tool_calls は2・3に増えたが、LLMが1回の応答で依頼をまとめて出したため（[tool call] が続けて並び、そのあと [tool return] が並ぶ）、requests は2のままだった。
  - 入力トークンは第1回の app.ask（7トークン）より大きく増えた。2回目のリクエストで、指示文・ツール説明・それまでのやり取り・検索結果を全部送り直すため。

- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int) -> str` を app/tools.py に追加し、app/agent.py で `agent.tool_plain(tools.make_quiz)` と登録した。
  - docstring：「指定した回の用語集から用語を1つ選び、確認問題と答えを返す。／『第2回の確認問題を出して』のように、確認問題を求められたときに使う。」
  - 処理：用語集から指定の回の用語を集める → 無ければ「第N回の用語は用語集にありません。」と返す → random.choice で1つ選ぶ → {"question": "「○○」の意味は？", "answer": 定義} を json.dumps で返す。
  - 用語が無い回の処理を入れたのは、空のリストに random.choice を使うと IndexError でプログラムが止まるため（実験で確認）。
  - 確認：--list-tools でツールが3個になり、自分の docstring が表示された。--trace で make_quiz({'lecture': 2}) が呼ばれ（「事前学習」の問題）、LLMは問題だけを出して答えは隠した。uv run pytest -q は 11 passed。
  - 気づき：生成AIはLLMだけでできていると見えていたが、実際はLLMとハーネスからできている。ハーネスは補助的なものだと思っていたが、ツールの実行（make_quiz で用語を集めて選んで返す処理）もハーネス側の仕事で、LLMは「make_quiz を2で」と頼むだけだった。サービスとしての生成AIは、LLMとハーネスの組み合わせでできていることがよく理解できた。
